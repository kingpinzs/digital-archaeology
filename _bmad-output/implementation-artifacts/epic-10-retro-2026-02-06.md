## What Went Well

### 1. Consistent Component Architecture
All 13 UI components followed identical patterns: mount/show/hide/destroy/isVisible/getElement lifecycle, CSS variables for theming, textContent-only for XSS prevention. This consistency made the codebase predictable and easy to extend.

### 2. Clean Three-Phase Build
UI components first, then data structures + engine, then integration. Story 10-17 (StoryController) wired everything together cleanly because the components were already solid.

### 3. Type Safety Foundation
types.ts and content-types.ts provided a strong foundation. The StoryContent→StoryAct→StoryChapter→StoryScene hierarchy with JSON Schema validation caught data issues at load time.

### 4. Zero Story Blockers
25 stories, no story blocked by another. The progressive build order was well-planned.

### 5. Mature Code Review Process
25 adversarial reviews across the epic. Story 10-25 found a HIGH severity CI bug (grep returning wrong test count). Story 10-24 review correctly scoped out a pre-existing era inconsistency.

### 6. Persona System Architecture
Stories 10-18 through 10-23 built an impressively deep persona immersion system: PersonaCard → ProfilePanel → TransitionPanel → MindsetProvider → DecisionMaker → DiscovererExperience. Each layer added depth without breaking prior work.

### 7. E2E Infrastructure Delivered
Story 10-25 delivered CI pipeline integration, Firefox cross-browser testing, persistence E2E tests, and discoverer E2E tests. 326 E2E tests across 2 browsers.

### 8. ~2,905 New Tests
Test suite grew from 971 to 3,876+. Substantial coverage growth for a feature-heavy epic.

## What Went Wrong

### 1. CRITICAL: Choices Don't Actually Branch
`StoryController.selectChoice()` at line 211-212 has an explicit comment: *"For now, choices advance to nextScene. Future: implement branching based on choice."* Every choice calls `engine.nextScene()` which reads `scene.nextScene` — ignoring the `choice.nextScene` property entirely. The JSON content has branching data (different `nextScene` per choice) that the engine never reads. **Every choice leads to the same page.**

**Evidence:**
- `StoryController.ts:208-216` — records choice for telemetry, ignores it for navigation
- `StoryEngine.ts:176-187` — `nextScene()` uses `scene.nextScene`, not `choice.nextScene`
- `act-4-micro4.json` — 3 choices with 3 different target scenes, all go to same `scene-4-1-2`

### 2. Story→Lab→Story Loop Is Broken
Returning from lab after challenge completion dumps the user on the same scene they left. `ChallengeStation.ts:100` calls `onReturnToStory()` which only switches the container visibility (`App.ts:618-631`). No call to `StoryController.nextScene()` or any story advancement mechanism.

**Evidence:**
- `App.ts:740-743` — `handleModeChange('story')` only hides/shows containers
- No `onReturnFromLab` callback exists in `StoryModeContainer.ts`
- No mechanism passes challenge completion state back to StoryController

### 3. Content Never Audited — 13 Issues Found
Deep audit of all JSON files revealed:
- **Missing persona file:** `first-counter-35000bc.json` referenced in `act-0-mechanical.json:17,56` but doesn't exist (Story 10-24 created the reference, never created the file)
- **Schema violation:** `story-schema.json:63` has `maximum: 5` for act numbers, but 11 acts exist (0-10)
- **Float chapter numbers:** act-0, act-2, act-6 use floats (1.5, 1.7, 2.5) when schema requires integers
- **Duplicate chapter number:** Two chapters numbered 3 in act-0-mechanical.json
- **Dead asset:** `babbage-1837.json` persona file unreferenced by any act

### 4. E2E Was Last, Not First
Epic 9 retro mandated "E2E testing mandatory for every story, effective immediately." Stories 10-1 through 10-24 shipped with zero E2E tests. E2E infrastructure was story 25 of 25.

### 5. Story Mode E2E Coverage Is 35%
Lab mode has ~80% E2E coverage. Story mode — the entire point of Epic 10 — has ~35%. Critical gaps:
- Multi-act progression: 0% tested
- Choice branching: 0% tested (broken anyway, see #1)
- Persona display: 10% tested
- Challenge round-trip flow: 15% tested
- Full discoverer experience (all 6 phases): 50% tested

### 6. Epic Was Oversized
25 stories is massive (Epic 9 had 8). Large epics make it harder to course-correct and spot systemic issues like the choice branching gap.

### 7. Event System Undocumented
Custom events (story-state-changed, challenge-progress-changed, mindset-established) were added story-by-story without a central event catalog.

## Root Cause Analysis

### Why Did Choice Branching Get Deferred?
The component pipeline (10-1 through 10-13) focused on rendering, not behavior. Story 10-15 (StoryEngine) implemented linear navigation as the baseline. Story 10-9 (ChoiceCard) only needed to emit a click event to be "done" by its AC. **No story's acceptance criteria required proving that choices affect outcomes.** The branching was a cross-cutting concern that fell between stories.

### Why Did the Lab Loop Break?
Story 10-11 (Enter Lab) tested that clicking the button switches modes. Story 10-13 (Challenge Objectives) tested that objectives track completion. Story 10-17 (Wire Integration) wired the forward path (story→lab). **No story was responsible for the return path advancing the narrative.** Each story passed its own AC but the system-level behavior was never assigned.

### Why Was Content Never Audited?
Story 10-24 was a content-only fix, not a code fix. Content changes have no CI validation gate — no schema check, no reference validation, no broken-link detection. **Code has lint, tests, and type-checking. Content has nothing.**

---

## Lessons Learned

### Architecture
1. **Cross-cutting behaviors need explicit stories** — branching, round-trip loops, and content integrity are system-level concerns that don't belong to any single component story
2. **Content is code** — JSON story files need the same CI validation as TypeScript: schema checks, reference validation, lint

### Process
3. **"Done" means the experience works, not just the component** — individual AC pass but the product doesn't function as intended
4. **E2E journey tests are different from E2E spot checks** — verifying a button exists is not the same as verifying a user can complete a workflow
5. **Tech debt comments in code ("Future: implement X") must be tracked** — the TODO at StoryController.ts:211 was invisible to the sprint process

### Technical
6. **Fallback navigation needs explicit fallback tests** — `scene.nextScene` as fallback when `choice.nextScene` is missing must be a tested code path
7. **State transitions between modes need bidirectional verification** — story→lab was tested, lab→story was not
8. **Schema validation must run in CI** — schema violations accumulated for 25 stories without detection

## Risk Assessment for Tech Debt Resolution

| Risk | Mitigation |
|------|-----------|
| TD-1 branching breaks existing linear navigation | Fallback to `scene.nextScene` when `choice.nextScene` is undefined; explicit unit test for fallback path |
| TD-3 content fixes cascade (renumbering breaks references) | CI validation script MUST exist before any content changes are made |
| TD-4 journey tests become flaky | Assert on structural selectors (`[data-scene-id]`, `.da-story-content`), not specific story text |
| Fixing gaps introduces new gaps | TD-4 journey tests serve as regression suite; run before AND after each TD fix |
