## What Went Well

### 1. Config-Driven Architecture (Story 11.2)
The centralized `stageConfig.ts` registry with typed `StageConfig` interfaces made every subsequent story predictable. Stories 11.4 through 11.7 asked "what does the config say?" instead of inventing resource discovery. The highest-leverage story in the epic.

### 2. Bridge Reinit Pattern (Story 11.3)
Instead of destroying and recreating bridge instances (losing event subscriptions), `reinit()` methods preserve subscriber maps across stage switches. Critical architectural decision that prevented UI state breakage.

### 3. Zero Regressions
4,229 unit tests, 34 E2E tests, zero regressions throughout the entire epic. Test suite grew 9% and stayed green.

### 4. Adversarial Code Review Process
34 issues found across 7 reviews — including a security bypass (URL could skip stage locking) and 3 race conditions. All fixed before merge.

### 5. Clean Tech Debt Execution
All 4 TD stories from Epic 10 retro completed before starting Epic 11. Clean foundation for infrastructure work.

### 6. Incremental Story Scoping
No rework, no backtracking. Each story built on the previous. Config system (11.2) → WASM loading (11.3) → syntax (11.4) → circuits (11.5) → examples (11.6) → routing (11.7).

---

## What Didn't Go Well

### 1. Brownfield Mindset in Greenfield Project
Agents defaulted to backward-compatible patterns — optional fields (`stage?: string` instead of `stage: LabStage`), defensive fallbacks for scenarios that can't happen, `INIT_WASM` backward compatibility for workers nobody runs in old mode. This is waste in a greenfield project with no production users.

**Impact:** Story 11.6 had to retrofit strict typing across 12 program entries and all tests. Work that wouldn't exist if types were strict from Story 11.2.

### 2. Async Race Conditions Missed in Initial Implementation
3 of 7 stories needed async guard flags (`isStageSwitching`, circuit reload race, `isRouteUpdating`), all caught in code review rather than initial implementation.

**Pattern:** The dev agent writes correct interfaces but doesn't systematically identify async state transitions and guard them.

### 3. Dead Code and Unused Parameters
Story 11.5 added a `stage` parameter to `mapStateToCircuit()` but never passed it from the call site. Story 11.1 had `VALID_LAB_STAGES` duplicating the `LAB_STAGES` array. The agent defines things correctly but doesn't trace data flow end-to-end.

### 4. Process Commitments Without Enforcement
3 of 7 Epic 10 action items were only partially followed — all process agreements, not concrete stories. Verbal commitments decay without workflow enforcement.

### 5. High Code Review Issue Rate
14 HIGH-severity issues across 7 stories = 2 per story average. The review process catches them, but first-pass quality needs improvement.

---

## Key Insights

1. **In greenfield agentic development, backward compatibility is waste, not safety.** No production users means no consumers to protect. Strict types from day one.

2. **If a process improvement matters, bake it into templates and checklists — not verbal agreements.** Agreements decay. Workflow enforcement persists.

3. **Async state transitions are a systematic blind spot.** The dev agent needs explicit prompting in Dev Notes to identify and guard them.

4. **Config registries with typed placeholders are the highest-leverage first story** in any infrastructure epic. Everything else becomes predictable.

5. **2 HIGH issues per story is the current baseline.** Target is zero HIGH by improving first-pass quality through better prompting in Dev Notes.

## Architectural Patterns Established

1. **Centralized Config Registry** — `stageConfig.ts` with typed interfaces, `ready: false` placeholders, DRY validation arrays
2. **Bridge Reinit** — Preserve event subscriptions, parallel async (`Promise.all`), error recovery with state revert
3. **Language Registry** — Lazy registration, fallback to Micro4 for unknown stages
4. **Stage-Aware Components** — Pass stage as parameter, generic fallback mappings, empty states for unavailable resources
5. **Hash-Based URL Routing** — GitHub Pages compatible, localStorage fallback, re-entrancy prevention

---

## Breakthrough Moments

1. **INIT_WASM Protocol (11.2)** — Workers can't import from main module system. Solution: pass WASM paths via postMessage. Enabled dynamic stage switching.
2. **Bridge Reinit Without Subscription Loss (11.3)** — `reinit()` preserves subscriber maps instead of creating new instances. Critical for UI stability.
3. **Lazy Example Filtering (11.6)** — ExampleBrowser is destroyed/recreated each open. Zero-complexity solution, no cache invalidation needed.
4. **Hash Routing for GitHub Pages (11.7)** — Avoids History API 404.html hack entirely. Clean URLs without deployment complexity.
5. **Re-entrancy Prevention (11.7)** — `isRouteUpdating` guard flag prevents infinite loop in bidirectional state sync.
