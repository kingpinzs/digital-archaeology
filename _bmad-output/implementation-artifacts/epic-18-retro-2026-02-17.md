## What Went Well

### 1. Layered Architecture — Zero-Rework Decomposition
The 5-story layering (Config → Enforcement → Education → Escape Hatch) was the standout pattern. Each story had a single responsibility, was complete and stable before the next started, and required zero changes to previous stories' code.

### 2. Bridge as Enforcement Layer
Constraint enforcement in `AssemblerBridge.ts` (TypeScript) instead of C WASM assemblers. Clean module boundary: C code remains stage-agnostic, TypeScript adds intelligence. Bypass logic for Story 18.5 was trivial as a result.

### 3. Educational Context as Progressive Enrichment
Story 18.4's three-layer error model (message → suggestion → educationalContext) provides progressively deeper understanding. The optional `educationalContext` field ensures perfect backwards compatibility.

### 4. Dramatic Code Review Quality Improvement
HIGH findings dropped from 2 per story (Epic 11) to 0.2 per story (Epic 18). Only 1 HIGH across 5 stories, caught in the first story and never repeated.

### 5. Consistent Error Builder Pattern
`buildMemoryConstraintError()` and `buildInstructionSetError()` follow identical patterns. Story 18.5's bypass was a one-line conditional wrapper: `if (!this.experimentationMode)`.

### 6. Tech Debt Resolution
Epic 18 resolved the hardcoded `256` memory view size from Epic 11's tech debt (replaced with `getStageMemorySize()`). Net-negative tech debt.

## What Didn't Go Well

### 1. CSS Variable Phantom References (Story 18.4)
Three undefined CSS variables (`--da-accent-info`, `--da-spacing-sm`, `--da-spacing-md`) introduced in Story 18.4. Fallbacks masked the issue. Fixed in code review by using hardcoded values matching existing patterns. This is the second epic with phantom CSS variables.

### 2. Test Helper Scoping and Duplication
Stories 18.4 and 18.5 both hit test failures because helper functions were scoped to sibling `describe` blocks. Story 18.5's status bar test required intricate mock setup (`contentChangeListeners.length = 0`, manual listener trigger, `assembleBtn.disabled === false` assertion). Multiple attempts needed.

### 3. JSDoc Inaccuracies
JSDoc mismatches between comments and actual data: 18.1 over-claimed C header sources for Micro32+ stages, 18.3 had incorrect mnemonic count (67 vs 68 for Micro8). Small but erodes documentation trust.

### 4. Non-Cumulative ISA Surprise (Story 18.3)
The story assumed instruction sets are cumulative supersets (Micro8 includes all Micro4 instructions). Wrong — LDA exists in Micro4 but NOT Micro8 (which uses `LD` instead). Required a rethink of constraint comparison logic. Should have been discovered during story creation.

### 5. Session Split (Story 18.5)
Story 18.5 was split across two sessions (Tasks 1-3 in one, Tasks 4-7 in another) due to context limits. While this worked, the continuity overhead was non-trivial.

## Key Insights

1. **Layered story decomposition (config → enforcement → education → escape) produces zero-rework epics.** Each story is complete and stable before the next starts. This should become the template for any "system" epic.

2. **Bridge-layer enforcement is the right pattern for web-wrapped native code.** Keep constraints in TypeScript while leaving WASM stage-agnostic. Preserves clean module boundaries and makes bypass logic trivial.

3. **HIGH code review findings dropped from 2/story (Epic 11) to 0.2/story (Epic 18).** The `readonly` mandate and greenfield mindset from Epic 11's retro directly reduced first-pass defects. Story template improvements work.

4. **CSS variable hygiene needs systematic enforcement.** Two epics in a row have introduced undefined CSS variables. A lint rule or variable inventory would prevent this.

5. **ISA documentation cannot assume cumulative supersets.** Each stage's instruction set must be independently verified against C source code. Domain assumptions are dangerous.

## Architectural Patterns Established

1. **Layered Constraint System** — Config data (stageConfig.ts) → Enforcement checks (AssemblerBridge.ts) → Educational enrichment (educationalContext) → Bypass toggle (experimentationMode)
2. **Error Builder Functions** — `buildMemoryConstraintError()`, `buildInstructionSetError()` as pure functions returning `AssembleResult`
3. **Three-Layer Error Model** — `message` (technical) → `suggestion` (actionable) → `educationalContext` (pedagogical)
4. **Instruction Metadata Registry** — `STAGE_INSTRUCTIONS` with `ReadonlySet<string>` for O(1) lookup, `findEarliestStageForInstruction()` for cross-stage awareness
5. **Settings Version Migration** — v1→v2→v3 chaining in `SettingsStorage`, `DEFAULT_SETTINGS.version` constant for type-safe version references

---

## Breakthrough Moments

1. **Non-Cumulative ISA Discovery (18.3)** — Instruction sets are NOT supersets. Each stage has its own independent instruction set. This prevented a class of false-positive constraint errors.
2. **Experimentation Mode as Conditional Wrapper (18.5)** — The bypass was a single `if (!this.experimentationMode)` guard on each enforcement check. The layered architecture made this trivial.
3. **Educational Content Progressive Enrichment (18.4)** — Optional `educationalContext` field provides historical/architectural "why" without changing existing error rendering. Perfect backwards compatibility.
4. **Tech Debt Resolution (18.1)** — Story 18.1 resolved the `TODO(CR M-1)` from Epic 12's code review — hardcoded `256` replaced with `getStageMemorySize()`.
