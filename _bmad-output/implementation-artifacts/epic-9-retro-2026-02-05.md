## What Went Well

### 1. Tiered Persistence Architecture
The architectural decision to use localStorage for settings, IndexedDB for projects, and File API for import/export was the right call. Each technology matched its use case perfectly:
- localStorage: synchronous, small data, settings
- IndexedDB: async, larger data, auto-save with 2-second debounce
- File API: explicit user-initiated import/export operations

### 2. Stories Built on Each Other Cleanly
Progressive story implementation created reusable infrastructure:
- 9.2's `ProjectStorage` class → foundation for 9.3's session restore
- 9.7's `confirmUnsavedChanges()` helper → reused in 9.6, 9.7, 9.8

## What Went Wrong

### 1. No E2E Tests - Relying Entirely on Unit Tests
3,722 unit tests but zero E2E tests. The persistence features are exactly where unit tests fall short:
- Auto-save timing across real page loads
- Session restore in actual browsers
- File downloads with real File API
- `beforeunload` behavior in real browsers

JSDOM workarounds (mocking Blob, File, beforeunload) masked real integration behavior.

### 2. Async Timing Bugs Were Subtle and Dangerous
- **9.2**: `setValue()` triggered `onContentChange` → `markDirty()` → auto-save 2s after page load (save-on-load loop)
- **9.3**: Map mutation during iteration when clearing stale breakpoints
- **9.8**: Cursor restoration needed `setTimeout` for Monaco DOM readiness

These bugs were only caught in code review, not tests.

### 3. Error Handling Maturity Was Inconsistent
- **9.4**: Launched with no `try/finally` for cleanup
- **9.5**: Added `try/finally` after learning from 9.4's review
- **9.6**: Applied pattern from the start
- It took 3 stories and multiple reviews to establish the pattern.

### 4. Code Duplication Built Up Across Stories
- Stories 9.3 and 9.8 had ~40 lines of identical breakpoint+cursor restoration code
- Not extracted until 9.8's code review created `restoreProjectToEditor()`
- Dev agent solved immediate problems without checking existing code

### 5. Platform Support Gaps
- 9.8's keyboard shortcuts initially only worked on Windows/Linux (Ctrl+)
- Missing macOS Cmd key support caught in code review
- Added `(e.ctrlKey || e.metaKey)` across all shortcuts

## Lessons Learned

### Architecture
1. **Tiered persistence is the right pattern** - each storage technology fits its use case
2. **Shared helpers emerge naturally from incremental stories** - let them grow organically, extract when duplication appears

### Process
3. **Unit tests alone can't catch integration bugs** - async timing, component interactions, and browser API behavior need E2E coverage
4. **Every error path needs a test** - code review repeatedly found untested `catch` blocks
5. **Dev agents should cross-reference existing code** - prevents duplication across stories

### Technical
6. **Async operations with DOM dependencies need lifecycle awareness** - `setTimeout` for DOM readiness, `autoSaveManager.cancel()` to prevent loops
7. **File API patterns require try/finally** - any operation allocating resources (URLs, DOM elements) needs cleanup in `finally`
8. **JSDOM limitations are real** - no `.text()` on Blob/File, hard-to-dispatch `beforeunload`, but workarounds are straightforward
